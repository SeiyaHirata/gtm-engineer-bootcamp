# ReServe合宿 受講生向けハンズオン①：ローカル環境構築

この合宿では、仮想予約SaaS「ReServe」の経営課題を**自分の手でSQLを叩いて診断**する。そのためのデータが入ったローカルDB（Supabase）と、画面の体感用モック（静的HTML）を、各自のPCで立ち上げる。

ここでは次の5ステップを通す。所要時間は初回イメージダウンロードを含めて**10〜20分**（回線次第）。

1. リポジトリを clone する
2. ローカルSupabaseを起動する（`supabase start`）
3. スキーマとシードを流す（`supabase db reset`）
4. Studioで `SELECT COUNT(*) FROM stores;` が **500** を返せば成功
5. モック（`mock/` のHTML）をブラウザで開く

> 当日のワークの主役は**SQL**。モックは「店舗・利用者が何に困るか」を体感するための画面で、**数字の判断には使わない**。詰まりの特定・通過率・ROIはすべてDB（SQL）で出す。

---

## 前提（事前にインストール済みのもの）

| ツール | 用途 | 確認コマンド |
|---|---|---|
| Docker Desktop | ローカルSupabaseはDockerコンテナ上で動く | `docker --version` |
| Supabase CLI | `supabase start` でローカルスタックを起動 | `supabase --version` |
| Git | リポジトリの取得 | `git --version` |

**Docker Desktopは「起動して常駐させておく」**（メニューバー／タスクトレイのクジラアイコンが緑）。起動していないと `supabase start` が失敗する。

### まだ入っていない人向け（導入リンク）

- Supabase CLI（公式・mac/Windows両対応）: https://supabase.com/docs/guides/local-development/cli/getting-started
  - **macOS**（Homebrew）:
    ```bash
    brew install supabase/tap/supabase
    ```
  - **Windows**（Scoop）:
    ```powershell
    scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
    scoop install supabase
    ```
- Docker Desktop:
  - macOS: https://docs.docker.com/desktop/install/mac-install/
  - Windows: https://docs.docker.com/desktop/install/windows-install/

導入後、上の「確認コマンド」でバージョンが表示されればOK。

## ステップ1：リポジトリを clone する

```bash
git clone https://github.com/SeiyaHirata/gtm-engineer-bootcamp.git
cd gtm-engineer-bootcamp
```

- 以降のコマンドは**すべてこのリポジトリ直下（`gtm-engineer-bootcamp/`）**で実行する。
- `supabase/`（config.toml・migrations・seed.sql）と `mock/`（モックHTML）が見えていれば正しい場所。

```bash
ls
# docs  mock  supabase  ...
```

---

## ステップ2：ローカルSupabaseを起動する

リポジトリ直下で：

```bash
supabase start
```

- **初回はDockerイメージのダウンロードが走るため数分かかる**（2回目以降は速い）。Docker Desktopが起動していることを必ず確認してから実行する。
- 完了すると、接続情報が表示される。重要なのは次の2つ。

| 表示項目 | 値 | 使い道 |
|---|---|---|
| Studio URL | http://localhost:54323 | GUI（SQL Editor）でファネルSQLを叩く |
| DB URL | postgresql://postgres:postgres@127.0.0.1:54322/postgres | psqlやGUIクライアントで直接つなぐ場合 |

> このリポジトリの `supabase/config.toml` では `[db.seed]` が有効になっており、`sql_paths = ["./seed.sql"]` を指定している。そのため **`supabase start` の時点で migrations 適用後に `seed.sql` が自動投入される**。多くの場合、ステップ2が終わった時点でデータは入っている。

---

## ステップ3：スキーマとシードを流す（確実に入れ直す）

`supabase start` で自動投入されるが、**「確実にまっさらから入れ直したい」「2回目以降で前のデータが残っているか不安」**なときは、次のコマンドで初期化する。

```bash
supabase db reset
```

- `supabase/migrations/`（スキーマ作成）をすべて適用し、続けて `supabase/seed.sql`（データ投入）を流し直す。
- シードは `generate_series` と固定タイムスタンプで作られた**決定論的データ**なので、**何度流しても同じ件数・同じ数字**になる。安心して実行してよい。
- 「データが変・件数が合わない」と思ったら、まずこのコマンドで入れ直すのが定石。

---

## ステップ4：Studioで動作確認（500が出れば成功）

1. ブラウザで **http://localhost:54323** を開く（Supabase Studio）。
2. 左メニューの **SQL Editor** を開く。
3. 次のSQLを貼り付けて実行する。

```sql
SELECT COUNT(*) FROM stores;
```

**結果が `500` なら環境構築は成功**。これでファネル分析に進める。

### 余裕があれば：6テーブルすべてに行が入っているか確認

`stores` 以外の主要テーブルにも行が入っているかを、一発で確認できる。**どのテーブルも件数が 0 より大きければ成功**（個々の件数は当日のワークで自分のSQLで出す）。

```sql
SELECT
  (SELECT COUNT(*) FROM stores)          AS stores,
  (SELECT COUNT(*) FROM billing_periods) AS billing_periods,
  (SELECT COUNT(*) FROM reservations)    AS reservations,
  (SELECT COUNT(*) FROM checkins)        AS checkins,
  (SELECT COUNT(*) FROM payments)        AS payments,
  (SELECT COUNT(*) FROM users)           AS users;
```

- `stores` が **500**、残り5テーブルが**すべて 1 以上**（行がある）なら、シードは正しく入っている。
- 各テーブルの中身（設定完了は何件か、キャンセルは何件か等）は**伏せてある**。これらは当日、自分でSQLを書いて数える対象。ここでは「6テーブルすべてに行があるか」だけ確認すればよい。

> ファネル各段の件数や通過率（なぜ登録から段々減るのか、何が詰まりなのか）は当日のワークで自分で解き明かす。事前確認では具体的な件数を出さない。

## ステップ5：モック（画面イメージ）をブラウザで開く

`mock/` 配下に、当日使う**静的HTML**が入っている。動かす必要はなく、**ダブルクリックでブラウザに表示するだけ**でよい（サーバー不要）。

| ファイル | 画面 | 体感したいこと |
|---|---|---|
| `mock/admin/A-01_onboarding.html` | 店舗オンボーディング | 「どこから手をつければいいかわからない」初期設定 |
| `mock/admin/A-03_dashboard.html` | 店舗ダッシュボード | 店舗に届く通知・一覧（うんざりの演出） |
| `mock/user/U-01_store.html` | 公開店舗ページ | 利用者の入口 |
| `mock/user/U-02_form.html` | 初回予約フォーム | 項目が多い＋送信ボタンに見えないCTA |
| `mock/user/U-03_confirm.html` | 予約確認（後払い表示） | 「払ってないから気軽にキャンセルできる」構造 |
| `mock/instructor/revenue-summary.html` | 収益サマリー（講師用） | ※当日コマ7で開示。事前に開かなくてよい |

開き方の例：

- **macOS**: `open mock/user/U-02_form.html`
- **Windows**: `start mock\user\U-02_form.html`
- うまくいかなければ、エクスプローラー／Finderでファイルを**ダブルクリック**してもよい。

> **重要：モックの数字で詰まりを判断しない。** 例えばダッシュボードに「キャンセル18件」と出ているが、これは**レイアウト確認用の仮の数字**で、DBの実データ（実際のキャンセル件数はSQLで出す）とは無関係。詰まりの特定・通過率は必ずSQL（ステップ4のDB）で出す。

## トラブルシュート

| 症状 | 原因 | 対処 |
|---|---|---|
| `supabase start` が `Cannot connect to the Docker daemon` 等で失敗 | Docker Desktopが起動していない | Docker Desktopを起動し、クジラアイコンが緑（Running）になってから再実行 |
| `port is already allocated` / ポート競合 | 54321〜54326 を別プロセスが使用中（前回の起動が残っている等） | まず `supabase stop` で停止 → 再度 `supabase start`。別アプリ（他のSupabaseプロジェクト等）が同ポートを使っていれば終了する |
| Studio（54323）が開かない | 起動途中、またはコンテナ未起動 | `supabase status` で各サービスの状態を確認。`supabase stop` → `supabase start` で入れ直す |
| `SELECT COUNT(*) FROM stores;` が0や想定外の値 | シードが入っていない／前のデータが残っている | リポジトリ直下で `supabase db reset` を実行してスキーマ＋シードを入れ直す |
| `relation "stores" does not exist` 等 | migrationsが適用されていない | `supabase db reset`（migrations適用→seed投入をやり直す） |
| `supabase` コマンドが見つからない | CLI未インストール、またはPATH未反映 | 上の「導入リンク」でCLIを入れ直し、ターミナルを再起動して `supabase --version` を確認 |

困ったときの基本セット（迷ったらこの順で）：

```bash
supabase stop          # 一度止める
supabase start         # 起動し直す（migrations + seed が走る）
supabase db reset      # それでもデータが変なら、スキーマ+seedを確実に入れ直す
supabase status        # 各サービスの状態とポートを確認
```

## 終わったら（合宿終了後の片付け）

合宿が終わってローカルスタックを止めたいときは、リポジトリ直下で：

```bash
supabase stop
```

データを完全に消したい場合は `supabase stop --no-backup` を使う（次回 `supabase start` で再びseedから作り直せる）。

---

ここまで完了すれば、当日は **Studio の SQL Editor で `stores` / `billing_periods` / `reservations` / `payments` / `checkins` を `COUNT` / `GROUP BY` / `HAVING` で叩き**、ReServeの「両側から漏れるバケツ」をデータで診断していく。
