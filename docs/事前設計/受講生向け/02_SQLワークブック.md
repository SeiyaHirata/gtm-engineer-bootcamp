# ReServe合宿 SQLワークブック（受講生向け）

> このワークブックはコマ2〜3で使う。**手を動かして、ReServeの売上課題を「数字で証明」するのが目的。**
>
> シリーズ4冊のうちのカリキュラムに対応した受講生用の課題集。答え（各段の件数・通過率・模範クエリ）は載せていない。**自分のSQLで出した数字をこのワークブックの記入表に書き込む**こと。

---

## 最初に読む（このワークの3原則）

1. **モックの数字で判断しない。** 店舗ダッシュボード（A-03）に出ている「キャンセル18件」などはレイアウト用の**演出の仮数字**。詰まりの特定・通過率・ROIは**すべてSQL**で出す。詰まりをモックの表示から答えたら、それは不正解扱いになる。
2. **分母は「前段」。** 通過率は「全体の母数」で割るのではなく、**ひとつ前の段で割る**。例：公開の通過率は `公開 ÷ 設定完了`（`公開 ÷ 登録` ではない）。
3. **詰まり＝他段から外れて低い段。** 全段が同じくらいの通過率なら健全。**1つだけガクッと低い段**が詰まり。低い段を名指しできれば勝ち。

> SQLはAIに書かせてもよい。だが「**どの段を疑い、どの通過率を異常と判断するか**」「リピートは健全だと切り分ける」のはデータと事業を知る人間の仕事。AIに丸投げすると、低い段を見落としたり、誤った分母で割ったりする。そこがGTMエンジニアの観点。

---

## 触るテーブル（シードDBの地図）

> 行数（各テーブルが何行か）は**自分で `SELECT COUNT(*)` して確かめる**。`stores` だけは 500 と分かっている（登録＝課金の母数）。それ以外の件数は課題で出す対象なので、ここには載せない。

| テーブル | これは何か | 主に使う列 |
|---|---|---|
| `stores` | 登録した店舗（500行）。オンボーディング段（設定・公開）だけここで見る | `id` / `is_setup_done` / `is_published` |
| `users` | 初回予約を完了した利用者（予約のFK用） | `id` |
| `billing_periods` | 月次課金の履歴。**継続はすべてここで数える**（1店舗最大3行） | `store_id` / `period_month` / `amount` / `status` |
| `reservations` | 予約。初回予約＋リピート予約 | `user_id` / `store_id` / `status` / `payment_timing` |
| `payments` | 来店時の後払い決済。GMVの源泉 | `user_id` / `amount` |
| `checkins` | 来店記録。`payments` と1:1 | — |

> **訪問40,000はテーブルにない定数。** ユーザー側ファネルの一番上「訪問」はSQLでは出ない。問題文で与えられた `40,000` を使う。
>
> **継続を `stores` で数えない。** 2ヶ月目・3ヶ月目の継続は `stores` には入っていない。**必ず `billing_periods` の `period_month` で数える**。これがよくあるミス。

## 課題A：二面のファネル各段を件数で出す

二面（店舗側・ユーザー側）のファネルを、上から順に1段ずつSQLで出す。**1段＝1クエリ**で構わない。出した件数は[記入表](#記入表ここに自分の数字を書く)に書く。

### A-1 店舗側ファネル（管理画面チーム）

#### A-1-① 登録＝初月課金

| 項目 | 内容 |
|---|---|
| 出すもの | 登録（＝初月に課金された店舗数） |
| 使うテーブル/列 | `billing_periods`（`store_id` / `period_month` / `status`） |
| ヒント | `period_month` が「初月」のものに絞り、`status` が課金成功のものを `COUNT(DISTINCT store_id)`。1店舗が複数行持つので `DISTINCT` を忘れない。 |

#### A-1-② 設定完了

| 項目 | 内容 |
|---|---|
| 出すもの | 初期設定を完了した店舗数 |
| 使うテーブル/列 | `stores`（`is_setup_done`） |
| ヒント | `is_setup_done` が真の行を `COUNT`。オンボーディング段は `stores` で見る。 |

#### A-1-③ 公開（掲載）

| 項目 | 内容 |
|---|---|
| 出すもの | 店舗ページを公開した店舗数 |
| 使うテーブル/列 | `stores`（`is_published`） |
| ヒント | `is_published` が真の行を `COUNT`。 |

#### A-1-④ 2ヶ月目継続

| 項目 | 内容 |
|---|---|
| 出すもの | 2ヶ月目も課金を続けた店舗数 |
| 使うテーブル/列 | `billing_periods`（`store_id` / `period_month` / `status`） |
| ヒント | `period_month` が「2ヶ月目」かつ `status` が課金成功のものを `COUNT(DISTINCT store_id)`。**`stores` では出ない**ことに注意。 |

#### A-1-⑤ 3ヶ月目継続

| 項目 | 内容 |
|---|---|
| 出すもの | 3ヶ月目も課金を続けた店舗数（＝当月サブスクの母数） |
| 使うテーブル/列 | `billing_periods`（`store_id` / `period_month` / `status`） |
| ヒント | `period_month` を「3ヶ月目」に変えて、A-1-④と同じ形で `COUNT(DISTINCT store_id)`。 |

### A-2 ユーザー側ファネル（ユーザー側チーム）

#### A-2-① 訪問

| 項目 | 内容 |
|---|---|
| 出すもの | 公開店舗ページへの訪問数 |
| 使うテーブル/列 | **テーブルなし（定数）** |
| ヒント | これはDBにない。問題文で与えられた `40,000` をそのまま使う。SQLで出そうとしないこと。 |

#### A-2-② 初回予約

| 項目 | 内容 |
|---|---|
| 出すもの | 初めて予約した利用者の数（初回予約） |
| 使うテーブル/列 | `reservations`（`user_id`）／必要なら `users` |
| ヒント | 初回予約をした「利用者」を数える。`COUNT(DISTINCT user_id)` で重複を除く。リピート予約と混ざらないよう、初回予約の利用者の母集団を意識する。 |

#### A-2-③ 来店確定（キャンセルなし）

| 項目 | 内容 |
|---|---|
| 出すもの | キャンセルされず確定した「初回予約」の件数 |
| 使うテーブル/列 | `reservations`（`status`） |
| ヒント | `status` が確定（`confirmed`）のものに絞る。ただし全体の `confirmed` にはリピート予約の確定も含まれるので、**初回予約の範囲だけ**を数える点に注意（初回予約の母集団＝A-2-②の対象）。 |

#### A-2-④ 初回来店（決済）

| 項目 | 内容 |
|---|---|
| 出すもの | 実際に来店して後払い決済した初回来店の件数 |
| 使うテーブル/列 | `checkins`（来店）／`payments`（決済） |
| ヒント | 来店＝決済（`checkins` と `payments` は1:1）。初回来店の件数を数える。 |

#### A-2-⑤ リピート

| 項目 | 内容 |
|---|---|
| 出すもの | 2回目以降も来店した利用者の数（リピーター） |
| 使うテーブル/列 | `payments`（`user_id`） |
| ヒント | 同じ `user_id` が**2回以上**決済しているかで判定。`GROUP BY user_id` してから `HAVING COUNT(*) >= 2`、それを `COUNT` する。 |

## 課題B：各段の通過率を割り算で出す

各段が「**前段から何%通過したか**」を割り算で出す。整数同士の割り算は小数にならないことがあるので、`* 100.0` や `::float` でキャストする。

> 通過率＝ **その段の件数 ÷ ひとつ前の段の件数**。
> 例：公開の通過率＝`公開 ÷ 設定完了`。**登録で割らない。**

| 段 | 通過率の式（分子 ÷ 分母） | 使うテーブル/列 | ヒント |
|---|---|---|---|
| 設定完了（店舗） | 設定完了 ÷ 登録 | `stores` / `billing_periods` | A-1-② ÷ A-1-① |
| 公開（店舗） | 公開 ÷ 設定完了 | `stores` | A-1-③ ÷ A-1-② |
| 2ヶ月目継続（店舗） | 2ヶ月継続 ÷ 公開 | `billing_periods` / `stores` | A-1-④ ÷ A-1-③ |
| 3ヶ月目継続（店舗） | 3ヶ月継続 ÷ 2ヶ月継続 | `billing_periods` | A-1-⑤ ÷ A-1-④。`billing_periods` だけで完結する。 |
| 初回予約（ユーザー） | 初回予約 ÷ 訪問 | `reservations` ／定数 | A-2-② ÷ 40,000（訪問は定数） |
| 来店確定（ユーザー） | 来店確定 ÷ 初回予約 | `reservations` | A-2-③ ÷ A-2-②。これがキャンセル率の裏返し。 |
| 初回来店（ユーザー） | 初回来店 ÷ 来店確定 | `checkins` / `reservations` | A-2-④ ÷ A-2-③ |
| リピート（ユーザー） | リピート ÷ 初回来店 | `payments` / `checkins` | A-2-⑤ ÷ A-2-④ |

> **発展（やれる人向け）** — 上の通過率を、サブクエリを使って**1本のSQL**で出してみる。`(SELECT ...)::float / (SELECT ...)` の形で、3ヶ月目継続の通過率などをまとめて出せる。

## 課題C：詰まりを特定する（他段から外れて低い段）

課題Bで出した通過率を二面とも並べる。**業界の通常値**は問題文（オリエン資料）で与えられている。比べて、**通常値より大きく外れて低い段**を名指しする。

| 観点 | やること |
|---|---|
| 並べる | 店舗側5段・ユーザー側4段（訪問→初回予約以降）の通過率を一覧にする |
| 比べる | 各段の観測値と通常値を横に並べる。差が大きい段ほど怪しい |
| 名指し | 「他段から外れて低い段」を**店舗側・ユーザー側それぞれ**で特定する |
| 切り分け | 通常値どおりの段は**健全**として除外する（全部が詰まりではない） |

考えるための問い（答えは書かない・自分で出す）：

- 店舗側で、通過率が通常値より大きく落ちている段はどこか（複数あるか1つか）。
- ユーザー側で、最初にガクッと落ちる段はどこか。その次に落ちる段はどこか。
- 通過率が通常値どおりで「健全（＝詰まりではない）」な段はどれか。**全部を詰まり扱いしないこと。**
- 後払い（`payment_timing` が `postpaid`）であることは、どの段の落ち込みと因果でつながるか。

> ヒント：詰まりは**店舗側に複数・ユーザー側に複数**ある。1つだけ見つけて満足しない。各段の通過率を全部出してから、外れている段を**全部**挙げる。
>
> ヒント：通過率が「通常値と同じ」段が1つある。そこは**健全**なので詰まりに数えない。これを詰まりに含めると不正解。

## 課題D：キャンセル件数・リピーター数・GMV・手数料を出す

詰まりの裏付けと、ReServeの売上（2つのキャッシュポイント）を数字で出す。

#### D-1 キャンセル件数

| 項目 | 内容 |
|---|---|
| 出すもの | キャンセルされた予約の件数（③bの裏付け） |
| 使うテーブル/列 | `reservations`（`status`） |
| ヒント | `status` がキャンセル（`cancelled`）の行を `COUNT(*)`。この件数が、来店確定の通過率の低さ＝高キャンセルの実態。**モックに出ている件数とは無関係。** |

#### D-2 リピーター数

| 項目 | 内容 |
|---|---|
| 出すもの | 2回以上来店・決済した利用者の数 |
| 使うテーブル/列 | `payments`（`user_id`） |
| ヒント | `GROUP BY user_id` → `HAVING COUNT(*) >= 2`。それを外側で `COUNT` する。課題A-2-⑤と同じ。 |

#### D-3 GMV（流通総額）

| 項目 | 内容 |
|---|---|
| 出すもの | 来店時に決済された金額の合計（GMV）＝手数料の母数 |
| 使うテーブル/列 | `payments`（`amount`） |
| ヒント | `SUM(amount)`。平均単価が気になるなら `AVG(amount)` も出す。GMVは「件数 × 平均単価」でも検算できる。 |

#### D-4 手数料（ReServeの変動収益）

| 項目 | 内容 |
|---|---|
| 出すもの | GMVに手数料率を掛けた、ReServeの月間手数料収益 |
| 使うテーブル/列 | `payments`（`amount`） |
| ヒント | `SUM(amount)` に手数料率（問題文で与えられた率）を掛ける。`ROUND(SUM(amount) * 手数料率)` の形。 |

> **発展** — ①店舗サブスク収益も出してみる。`3ヶ月目継続の店舗数 × 月額`（月額は `billing_periods.amount` を `DISTINCT` で取れば固定値が分かる）。サブスク収益＋手数料収益＝ReServeの月商。

## チェックリスト（提出前に自分で確認）

- ☐ 通過率を**前段**で割っている（全体の母数で割っていない）
- ☐ 継続（2ヶ月・3ヶ月）を `stores` ではなく `billing_periods` の `period_month` で出している
- ☐ 件数を `COUNT(DISTINCT ...)` で出すべき段で `DISTINCT` を付けている
- ☐ リピーターを `HAVING COUNT(*) >= 2` で出している
- ☐ 詰まりを**店舗側・ユーザー側それぞれ複数**名指しできている
- ☐ 通常値どおりの段を**健全**として除外している（全部を詰まりにしていない）
- ☐ 詰まりの特定を**モックの表示数字ではなくSQL**で行っている
- ☐ GMV・手数料・キャンセル件数・リピーター数を出している

> 提出物（コマ2ワーク）：**チーム別ファネル表＋詰まりの名指し＋2つのキャッシュポイント（サブスク・手数料）の値**。次のコマ3では、ここで特定した詰まりに対して施策を出し、工数×インパクト＝ROIで並べる。
