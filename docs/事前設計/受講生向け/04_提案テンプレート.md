# 提案テンプレート（コマ5でうめる空欄ひな形）

> このファイルはコマ5でうめる**空欄テンプレ**です。`______` や `（　　）` を、自分たちが SQL で出した数字・ブレストで出した施策で置き換えてください。
>
> **絶対ルール（評価の核）**
> 1. 数字は**すべて SQL で出した実値**を使う。モックのダッシュボードに出ている件数（キャンセル18件 等）は**演出用の仮数**なので使わない。
> 2. インパクトは**改善%だけ書かない**。必ず**ファネルの Before / After / 差分**を書いてから年間リターンを出す。
> 3. リターンは**2軸を混ぜない**。
>    - 管理画面側（①②）＝（増えた**3ヶ月目継続店舗数**）× 12,000円 × 12ヶ月
>    - ユーザー側（③a③b）＝（増えた**来店決済件数**）× 4,000円 × 1% × 12ヶ月
> 4. コスト＝**工数（時間）× 5,000円**（時給5,000円）。ROI＝**年間リターン ÷ コスト**（倍）。
> 5. 優先度は「目立つ詰まり」「自分のチームの詰まり」ではなく、**全施策のROI順**で決める。
>
> （参考の計算ルール・工数目安・下流係数は本ファイル末尾の「付録」に置いてあります。迷ったらそこを見てください。）

## 付録：埋めるときに見る計算ルール

> 迷ったらここを見る。これは「答え」ではなく「計算の型」。

**コスト・ROI**
- コスト ＝ 工数（時間）× 5,000円
- ROI ＝ 年間リターン ÷ コスト（倍）

**リターンの2軸（混ぜない）**
- 管理画面側（①②）＝（増えた3ヶ月目継続店舗数）× 12,000円 × 12ヶ月
- ユーザー側（③a③b）＝（増えた来店決済件数）× 4,000円 × 1% × 12ヶ月

**インパクトの読み方（4ステップ）**
1. 改善する段を1つ指定する
2. その段の通過率を Before → After で置く
3. 母数は固定、下流は**既存の通過率**を掛けて After 件数を出す
4. 最終段（店舗側＝3ヶ月継続／ユーザー側＝来店決済）の差分からリターンを出す

**下流係数（施策後もこの通過率を使う。各通過率はコマ2で自分が出した実値を使う）**
| 起点 | 下流までの掛け算 |
|---|---|
| ① 設定完了 → 3ヶ月継続 | × 公開`__%` × 2ヶ月`__%` × 3ヶ月`__%`（各通過率はSQLで出した実値） |
| ③a 初回予約 → 来店決済 | × 来店確定`__%` × 来店`__%`（各通過率はSQLで出した実値） |
| ③b 初回予約 → 来店確定 | 初回予約件数を母数に据え置き、確定率だけ変える |
| ② 2ヶ月 → 3ヶ月継続 | 2ヶ月継続を母数に据え置き、3ヶ月通過率だけ変える |

**AI時代の工数目安（実装にかかる時間）**
| 施策の種類 | 目安時間 |
|---|---|
| 文言・表示の変更 | 2〜4時間 |
| UI部品の追加・フォーム削減 | 4〜8時間 |
| 画面フローの組み替え（ウィザード化等） | 12〜24時間 |
| 通知・メール追加 | 4〜8時間 |
| 決済・課金ロジック変更（デポジット等） | 40〜64時間（AIでもそこまで縮まない） |

**やりがちなNG（FBで戻される）**
- 1詰まり1施策で終わっている
- 改善%だけ書いて、ファネル下流の件数差分を出していない
- モックのダッシュボード数字（キャンセル18件等）から詰まりを特定している → SQLに戻す
- 自分のチームの詰まりを最優先にしている → 全体ROI順で並べる
